macmon · RAM box

Reading macOS memory

macmon splits RAM the way Activity Monitor does. The colored bar spans your Mac's total physical RAM, so the whole width is 64 GB on a 64 GB machine. What matters is not how full the bar is, but which colors fill it.

macmon draws with your terminal's ANSI colors, so the shades follow its theme. This page uses Ghostty's Desert theme: magenta, blue and cyan come out as wheat, tan and pink there.

The five kinds, left to right

What each color holds

wired
Activity Monitor: Wired Memory

Memory pinned in place. The kernel and drivers need it to stay exactly where it is, so macOS can never compress it or move it to disk.

never reclaimed until its owner lets go

Examples: the kernel itself; GPU buffers, including a local LLM's weights and context cache. A 30 GB Ollama model shows up here, not under the ollama process's app memory.

app
Activity Monitor: App Memory

Data programs created while running, with no file behind it on disk. If macOS needs the room, it has to compress this memory or write it to swap first.

reclaimed at a cost compress, then swap

Examples: browser tabs, an editor's open buffers, a compiler's working state, Spotify's decoded audio.

comp
Activity Monitor: Compressed

App memory that hasn't been used lately, squeezed in place instead of written to disk. The bar shows the RAM the compressor occupies. The legend's ×2.1 is how much data it holds per GB it uses.

reclaimed at a cost swap out the compressed pages

Examples: background tabs you haven't looked at in an hour. Touching them costs a little CPU to decompress, which is far cheaper than reading from disk. A growing cyan section means macOS is working to make room.

cache
Activity Monitor: Cached Files

Copies of files already on disk, kept in RAM in case they're read again, plus memory apps have marked as disposable (purgeable). Dropping it costs nothing, since the original is still on disk.

free in all but name dropped instantly

Examples: a project you just built, a video you just watched, model weights Ollama read from disk on load. This is why "used RAM is high" is often harmless.

free
The blank end of the bar

RAM holding nothing yet. macOS fills it with cache whenever it can, so a small free section on a busy Mac is normal and expected.

Beyond the bar

Two signals that tell you if it hurts

Memory pressure

normalwarningcritical

The kernel's own verdict, the same one Activity Monitor graphs. It accounts for how much is reclaimable and how hard the system is working. macmon shows it on the RAM box's top border and colors the history graph with it, so a full bar with a green graph is fine.

Swap activity

SWAPSWAP⇅SWAP⇅ ≥10 MB/s

Swap is app memory written to the SSD. How much sits there says little: data stays in swap for hours after the crunch ends. Swapping right now is what makes apps stutter, so macmon colors the SWAP figure only while data is moving.

Rules of thumb

Reading it at a glance

  1. Look at the graph color before the percentage. Green pressure means memory is fine, however full the bar looks.
  2. Grey is free memory waiting to be useful. A bar full of grey is a healthy Mac.
  3. A large magenta (wired) section is usually a GPU workload. Local LLMs live here.
  4. Growing cyan (compressed) means macOS is making room. It's the early warning before swapping.
  5. SWAP⇅ in yellow or red is the slowdown itself. A big swap total with a plain SWAP figure is old news.
